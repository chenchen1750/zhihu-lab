# 定位

## 一句话

**一个用工程方法管理职业生涯的 SRE。**

## 差异化

知乎职场答主基本两类：HR / 培训师讲道理，大厂人讲故事。这两条赛道都挤满了，且没有壁垒。

我们的壁垒有四条：

1. **一套成文的规则库。** `km-harness/knowledge/` 有 337 条带 id、来源、适用与不适用、怎么用的条目（其中 79 条命中职场域）。
   别人说「要复盘」，我们能直接给四步十项 + KPT + 频次怎么调（T-0087）。
2. **SRE 视角迁移。** 把稳定性、治理、成本的工程方法用在职场上。知乎上几乎没人这么写。
3. **一人 + Agent 的敏捷团队（F-0060）。** PO 是人，PM / SM / TL / 工程团队都是 agent。2026 年最稀缺的选题，而且我们已经在跑。
4. **真实且不体面的职场情境。** 方案被推翻、技术选型被行政理由否决、纠正了错误却被挤出主导位。这类细节最值钱，也最难被抄。

## 内容与收益的关系（别搞混）

知乎**回答本身的直接收益很低**。这套职场系列的目标是**建账号权重和人设**，不是变现主体。

变现路径是另外三条：盐选签约（→ `../short-story-lab`）、好物推荐、付费咨询 / 私域。

所以：职场回答线和短篇创作线**分开算 ROI**，不要用回答的赞数去衡量「写作月收入」这个目标。

## 出手顺序

`S-01 → S-03 → S-04 → S-02 → S-05`

- S-01 最差异化、最容易被推荐，先打
- S-05 流量最大但竞争最惨烈，纯观点很难出头，等前面几个系列把权重和人设立起来再进

## 产出方式

每个系列先写一篇**母文**（发专栏），再拆成 3–5 个**回答**。
回答重写开头和结尾针对具体问题，中段复用母文骨架。
这是知乎常规打法，也正好是「先建结构，再持续维护」（P-0069）本身。
