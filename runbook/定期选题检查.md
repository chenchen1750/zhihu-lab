# 定期选题检查

挂在「周三主题：滚动规划、资源收集」下跑，每周一次，15 分钟。
季度做一次大盘（见最后一节）。

## 每周流程

### 1　扫描（2 分钟）

```bash
cd ~/workidr/zhihu-lab
python3 tools/zhihuctl.py scan
```

看三段输出：

| 输出段 | 要做的判断 |
|---|---|
| **新增条目** | 上周 km-harness 长出来的新条目。每条看一眼：能不能挂到它下面列出的某个问题上？能就记下 `问题id ← 条目id` |
| **内容有更新的条目** | 已经引用过的条目被改写了。检查引用它的问题，角度要不要跟着调 |
| **待办** | P0 还躺在 inbox 的、进了 active 却没动笔的、热度还没人工核对的 |

新增条目为空是正常的 —— 说明上周没提炼出新东西，不是工具坏了。

### 2　挂载（5 分钟）

把认下来的条目写进对应问题文件的 `matched_entries`，同时在正文「可用条目」小节补一句怎么用。

改完跑：

```bash
python3 tools/zhihuctl.py validate && python3 tools/zhihuctl.py index
```

`validate` 会检查条目 id 在 km-harness 里真实存在，写错会报错。

### 3　起题（5 分钟）

对照 `questions/REVIEW.md` 的五条判断，挑 inbox 里够格的进 active：

```bash
python3 tools/zhihuctl.py promote Q-0001
```

**进 active 的硬条件**：`matched_entries` 至少 2 条，`angle` 写得出一句和高赞不一样的话。
两条不满足就别 promote，留在 inbox 写清缺什么。

同一时间 **active 不超过 3 个**。超了就是在囤，不是在写。

### 4　收尾（3 分钟）

```bash
python3 tools/zhihuctl.py scan --commit
```

确认看过之后再 commit，下周才只报增量。

## 发现新问题时

平时刷到值得答的问题，当场登记：

```bash
python3 tools/zhihuctl.py new \
  --title "问题原标题" \
  --url "https://www.zhihu.com/question/12345678" \
  --series S-03 --priority P1 \
  --entries "T-0053,R-0115" \
  --angle "一句话说清你的角度"
```

只收 `www.zhihu.com/question/...`。专栏 `zhuanlan.zhihu.com/p/...` 不能回答，
要留就写进问题文件的「竞品观察」小节。

## 写完发布后

发布前先过机器检查，再过人眼：

```bash
python3 tools/zhihuctl.py lint --fix     # 人称、脱敏红线、条目引用、字数
```

`lint` 命中脱敏红线会非零退出，必须清干净再发。人称命中的逐条确认是不是
CLAUDE.md 里允许的三条例外。

发布后回填：

```bash
python3 tools/zhihuctl.py promote Q-0001 --url "https://www.zhihu.com/question/xxx/answer/yyy"
python3 tools/zhihuctl.py index
```

## 季度大盘

每季度末多做三件事：

1. **人工核对热度。** 知乎反爬，脚本拿不到关注数。在 App 里把 active + P0 的问题看一遍，
   填 `followers` / `answers_count`，更新 `checked`。冷掉的问题降级或 drop。
2. **回看数据。** `answered/` 里每篇的赞藏比、涨粉。哪个系列真的有效，下季度加码；
   没效的降优先级，别because「计划里写了」就硬写。
3. **清重复。** 同系列角度高度重合的，按 `REVIEW.md` 第 5 条二选一：
   `python3 tools/zhihuctl.py drop Q-00xx --reason "与 Q-00yy 重复"`

## 这套东西本身也要维护

`P-0069`：治理 = 先建结构 + 持续维护。

这个 runbook 是结构。如果连续三周 scan 跑出来都没人动 —— 那就是结构建完没维护，
和那篇文章里写的一模一样。到那时候要么改流程要么承认不做，别让它烂在仓库里。
